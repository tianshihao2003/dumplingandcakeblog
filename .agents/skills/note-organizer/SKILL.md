# 学习笔记整理（团子和蛋糕的博客）

## 唯一规范来源：先读，别凭记忆

**规范正文 = `src/content/posts/编程学习/学习方法/笔记整理规范.md`**

每次整理笔记（含改文件名、改 frontmatter、补图片）之前，**先读这篇**，并严格执行其中所有规则：命名编号、编号维护、frontmatter 字段、标签、图片判据与存放、正文结构、验证与回报。

> 规范要改时**只改那一篇文章**。本技能文件只在两种情况才动：① 规范文章换了路径 ② 执行流程（下面的步骤）变化。用户说"这条规范采用"时，改文章即可，不要在这里再存一份副本。

## 配套的两篇文章（改一处，另一处按情况同步）

| 文章 | 作用 | 什么时候要改 |
| --- | --- | --- |
| `编程学习/学习方法/笔记整理规范.md` | **规则正文**：命名编号、frontmatter、标签、图片、正文结构、练习题规范 | 规则变化时改这里（唯一规则来源） |
| `编程学习/学习方法/笔记整理与出题助手使用说明.md` | **用户手册**：触发词、一次完整流程、文件位置、常见问题、更新记录 | **技能有新功能或功能变化时必须同步更新**（用户明确要求），并在它的「更新记录」表加一行 |

## 执行流程

> 整理资料（笔记）走下面流程；**出题 / 批改 / 重做**走下面「练习题」那一节。

1. **读规范**（上面的文章）
2. **读资料**：多张图一张不落读完再动笔；PPT/PDF 里**没有文字的纯图页也要逐张看图**（文字提取不到 ≠ 没内容）。边读边记「看不清 / 被截断 / 有疑问」的清单，最后必须回报用户
3. **索引现状**（不许凭印象，用命令查）：
   - 目标目录：`ls` 看现有编号排到几号、文件命名风格
   - 标签词表：扫一遍现有文章 frontmatter 的 tags，只从里面挑
   - 同主题是否已有笔记 → 决定新建还是追加
4. **写**：按规范里的编号、frontmatter、图片、正文结构执行
5. **验证**：`pnpm build`（zod 校验字段 + 图片路径解析，写错会直接报错）
6. **回报**：改动文件清单 + 补全了哪些知识点 + **存疑清单** + 构建结果

## 练习题（出题 / 批改 / 重做）

规范在**同一篇文章的第十节**（10.1-10.8），执行前先读那一节。四条最容易漏的硬规矩：

1. **笔记是唯一来源**：题目、分级提示、答案只写在笔记末尾的 `## 练习题`；练习文件由笔记生成，**里面不放答案**。
2. **生成练习文件时只刷新顶部题目注释块**（到第一个 `# 在下面写你的代码：` 之前），**用户写的代码一字不动**；综合题只在文件不存在时创建。
3. **禁止答案级提示**（`-> list.append(元素)` 这种），提示一律放进折叠块 `> [!TIP]-`，分三级（思路 → 方法名 → 骨架）。
4. **交付前必须验证**：能在本机跑的答案（文件操作、json、os、纯逻辑）**实跑一遍**；需要 API Key / Streamlit 运行时的至少过语法编译，并对照笔记里已验证的完整代码核对。批改时也要真跑用户的代码，不靠肉眼。

批改结论写回**笔记里对应题目下面**（不建错题本），错题在题目行打 `❌`；`重做错题` 就是扫带 `❌` 的题生成 `retry_NN_主题.py`。

## 常用工具

- `node scripts/vision.mjs <图片路径> "<问题>"` — 视觉模型识图（OpenAI 兼容，不给路径时自动取最新图片）
- `pnpm cli desc` — AI 批量补全缺失的 description（不覆盖已有）
- PPT 取文字/取图：`unzip -q 文件.pptx -d <临时目录>`，文字在 `ppt/slides/slideN.xml`（`<a:t>` 标签内），图片在 `ppt/media/`；中文字体与排版信息会丢失，代码以附带的真实源码文件为准
- 批量改链接/字段：写 Node 脚本（仓库规则：**禁止用 Python 操作文件**），预演（只打印）→ 确认无误 → 再 `--apply`
- ⚠️ **`git mv` 的坑**：它只搬索引里的**旧内容**，工作区新改的内容不会进暂存（状态显示 `RM`，容易漏出提交）。重命名 + 改内容同时做时，顺序要么「先改内容 → `git mv` → 再 `git add` 一次」，要么搬完统一 `git add`，提交前用 `git diff --cached` 核对内容确实带上了。
