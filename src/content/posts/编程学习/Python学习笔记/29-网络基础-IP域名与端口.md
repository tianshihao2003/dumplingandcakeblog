## 为什么调用大模型前要先学网络

调用大模型 API 的本质是**客户端通过网络向服务端发一个请求**：

```text
客户端（你的 Python 程序） ──网络(协议、IP/域名、端口)──> 服务端（DeepSeek）
```

网络四通八达就像城市的复杂道路，数据就像车流。要保证数据不混乱，就需要统一的规则。

## IP 地址

IP 地址可以理解为设备在互联网中的地址（唯一身份证），每一个连入网络的设备都有一个自己的 IP 地址，用来定位设备在互联网中的位置。

| 版本 | 位数 | 说明 |
| --- | --- | --- |
| IPv4 | 32 位二进制 | 分成 4 段，每段十进制取值 0~255，例如 `132.12.86.125` |
| IPv6 | 128 位二进制 | 地址数量更大，格式为十六进制冒号分隔 |

> [!NOTE]
> `127.0.0.1` 是一个非常特殊的 IP 地址，表示的是**本机地址**（也称为本地回环地址）。访问它永远是访问你自己这台机器。

## 域名与 DNS

域名（Domain Name）是由一串用点分隔的英文字母组成的。IP 地址不便于记忆，因此设计出了域名，并通过 **DNS（域名解析服务器）** 将域名和 IP 地址相互映射，便于记忆和访问。

```text
www.baidu.com  ──DNS 解析──>  110.242.69.21
```

- 好处：人记域名，机器用 IP
- `localhost` 就是本机域名，等价于 `127.0.0.1`

## 端口号

端口号（Port）是整数，取值范围 **0-65535**，用来标识计算机设备中**正在运行的程序**。

- 同一个 IP 上可以跑很多程序，靠端口区分是哪一个在接收数据
- `HTTP` 协议默认端口号为 **80**，`HTTPS` 协议默认端口为 **443**

> [!TIP]
> 因为浏览器会自动补上默认端口，所以访问 `https://www.baidu.com` 时你不必写 `:443`。

## 网络模型

互联网（Internet）连接了数以亿计的设备，ISO 组织统一了程序在网络中通信的模型和标准：

| OSI 七层模型 | TCP/IP 四层模型 | 职责 |
| --- | --- | --- |
| 应用层、会话层、表示层 | 应用层（HTTP、FTP、SMTP） | 将用户与应用程序交互的数据按照协议格式进行封装 |
| 传输层 | 传输层（UDP、TCP） | 负责将数据准确地送到对应的应用程序（端口） |
| 网络层 | 网络层（IP） | 负责基于 IP 地址将数据包路由给对应设备 |
| 数据链路层、物理层 | 网络接口层 | 负责数据在物理网络中的传输，处理与硬件设备交互 |

- **OSI 网络模型**：全球网络互连标准模型（7 层，偏理论）
- **TCP/IP 网络模型**：可以认为是 OSI 的简化版（4 层，实际使用）

## 小结（复习自测）

| 题目 | 答案 |
| --- | --- |
| IP 的作用 | 唯一定位一台互联网上的设备（`127.0.0.1` 为本机地址） |
| 域名的作用 | 降低 IP 地址的书写与记忆成本（`localhost` 为本机域名） |
| 端口的作用 | 每一个程序启动运行后都会占用一个端口（0-65535） |
| TCP/IP 四层网络模型 | 应用层、传输层、网络层、网络接口层 |
