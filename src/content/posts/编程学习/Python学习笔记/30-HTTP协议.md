## 什么是 HTTP

Hyper Text Transfer Protocol，超文本传输协议，规定了**客户端和服务器之间数据传输的规则**。

只有在请求及响应中都遵循了统一的规则，服务端才能读懂客户端发送来的请求，客户端才能解析服务端响应的结果。

### 三大特点

| 特点 | 含义 |
| --- | --- |
| 基于文本的协议 | 请求和响应部分的协议内容为文本格式，底层通过 TCP 协议传输，稳定性强 |
| 基于请求-响应模型 | 一次请求对应一次响应，必须由客户端先发起请求，服务端才会返回响应 |
| 无状态 | 服务端不会记忆与客户端的历史交互信息，每次请求-响应都是独立的 |

> [!IMPORTANT]
> "无状态"这一条是理解 AI 会话记忆的关键：AI 大模型的交互同样是无状态的，模型本身没有记忆，所谓"记得上一句"是客户端把历史消息一起发过去了。详见 [实战-AI智能伴侣-会话记忆](/posts/编程学习/python学习笔记/38-实战-ai智能伴侣-会话记忆/)。

## 请求数据格式

一次 HTTP 请求由三部分组成：

| 部分  | 内容                       |     |
| --- | ------------------------ | --- |
| 请求行 | 请求方式、资源路径、协议             |     |
| 请求头 | 格式为 `key: value`         |     |
| 请求体 | 请求参数部分，GET 方式没有，POST 可以有 |     |

下面是抓到的**真实请求数据**（一个 POST 请求的完整报文）：

![HTTP 请求报文示例](https://img.tsh520.cn/file/blog/article/http-request-raw(1).png)

对照着看三部分在哪：

- `POST /api/courses HTTP/1.1` 是**请求行**：请求方式是 POST，资源路径是 `/api/courses`，协议版本 HTTP/1.1
- 中间一串 `key: value`（`Host`、`Content-Type`、`User-Agent` 等）是**请求头**
- 最后一行是**请求体**，这里放的是 JSON 格式的请求参数

### GET 与 POST 的区别

| 对比项 | GET | POST |
| --- | --- | --- |
| 参数位置 | 在请求行中，没有请求体 | 在请求体中 |
| 示例 | `/api/courses?name=Python&status=1` | 请求体里放 JSON 等数据 |
| 大小限制 | 浏览器中请求参数大小有限制 | 请求大小没有限制 |

## 响应数据格式

| 部分 | 内容 |
| --- | --- |
| 响应行 | 协议、状态码 |
| 响应头 | 格式为 `key: value` |
| 响应体 | 存放服务端响应的数据 |

这是上面对应的**真实响应数据**：

![HTTP 响应报文示例](https://img.tsh520.cn/file/blog/article/http-response-raw.png)

- `HTTP/1.1 200` 是**响应行**：协议版本 + 状态码 200（请求成功）
- 中间是**响应头**（`Server`、`Date`、`Content-Type` 等）
- 最后是**响应体**：`{code: 1, msg: "success", data: null}`

### 常见状态码

| 状态码 | 含义                          |
| --- | --------------------------- |
| 200 | 客户端请求成功                     |
| 400 | 请求参数错误                      |
| 404 | 请求资源不存在，url 输入有误，或者网站资源被删除了 |
| 500 | 服务器发生了不可预期的错误               |

> [!TIP]
> 排查调用大模型接口报错的顺序：先看状态码。**400 多半是请求体写错**（例如 JSON 的 key 没加双引号、`model` 名字写错），**401 说明 API Key 没带上或已失效**，**404 说明 url 写错了**。

## 小结（复习自测）

| 题目 | 答案 |
| --- | --- |
| 请求格式 | 请求行（请求方式、资源路径）、请求头（key:value）、请求体（POST 方式才有） |
| 响应格式 | 响应行（状态码）、响应头（key:value）、响应体 |
| HTTP 的特点 | 基于文本的协议、基于请求响应模型、无状态 |
